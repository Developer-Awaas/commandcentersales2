| 45 | Canva "Edit in Canva" flow — major overhaul (2026-07-25 through 2026-07-27) | A multi-day investigation across several distinct, stacked bugs, developed and fully live-tested on review-build before porting here. **What was actually wrong, in the order discovered**: (a) the cold-start OAuth connect did a same-window `window.location.href` redirect, wiping all in-page React state (the generated strategy + images) with no way back; | 47 | `dhruv-anomaly-check` + `dhruv-weekly-report` (`notifications` insert) | Both Edge Functions inserted `body: …` into `notifications`, but the column is **`message`** (`notifications` cols: `id, org_id, user_id, title, message, type, is_read, created_at`). Supabase-js `.insert<T>()` infers its argument as a **generic type parameter**, which suppresses TypeScript's excess-property check — so a wrong key like `body` compiles cleanly and passes `deno check`, then at runtime PostgREST rejects the unknown column and `.insert()` **returns `{ error }` rather than throwing**. Result: `dhruv-anomaly-check`'s alert notifications **never persisted since inception** (the error was logged and the org marked `alerts_fired:0`, but no row ever wrote — the `tool_outputs`/console path masked it); `dhruv-weekly-report` (CC-P4) shipped the same typo, so its weekly-report notification silently no-op'd too (the `tool_outputs` report row + `agent_interactions` cost row *did* write correctly — only the notification was lost). **Found** while gathering CC-P4 cron-path evidence: the report row existed but the `weekly_report` notification query returned zero rows. **Fix**: `body` → `message` in both functions; `dhruv-weekly-report` now also captures + logs `notifErr` (it previously didn't check the insert result at all). Lesson: a wrong column name on a Supabase `.insert()` is invisible to `deno check` and never throws — always `select` the write back (or check `.error`) when verifying a new insert path; the type system will not catch it. |

| 49 | `generate-image/index.ts` (plain text-to-image branch) | Quick Generate and SMM Creatives both failed with `Signal timed out.` at **exactly 135s**, twice each, on 2026-08-29.
