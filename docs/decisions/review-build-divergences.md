## Meta Publishing (RB-PUB)


Everything before this read from Meta. `meta-publish` writes to a Facebook Page or Instagram account. The safety rails were built before the happy path, and they are the part to preserve.

**TWO INDEPENDENT GATES, different owners.** A publish needs both:
1. `org_integrations.publish_page_id` — the org's CHOSEN target, set by an admin in Settings → Publishing. **Never `meta_page_id`**, which is *discovered* (whatever `/me/accounts` listed first) and on this deployment's token is a real customer's Page. Publishing to a discovered value would make the destination of a post a side effect of an unrelated sync.
2. `PUBLISH_ALLOWED_PAGE_IDS` — a comma-separated Edge Function **secret**, not a table. No code path writes it, so the set of Pages a deployment can post to is fixed at deploy time by someone with project access, and a bad org row (bad migration, bad admin click) is refused anyway.

**FAIL-CLOSED**: unset or empty `PUBLISH_ALLOWED_PAGE_IDS` refuses EVERY publish, naming the missing config. The opposite default ("no list, so allow anything") is the shape of every accidental-broadcast incident and fails open exactly when a misconfiguration makes it most dangerous. Tested in `_shared/meta-publish_test.ts`.

**Gate order in `meta-publish/index.ts`** — valid JWT (org from the JWT, never the body) → active connection → `meta_verified_at` set (unverified provenance cannot publish, per the dead-app incident in `20260818120000`) → org-chosen target → allowlist → content validation → `dry_run === false`. An omitted or malformed `dry_run` is treated as **true**: the only way to reach Graph is to say so explicitly.

**Dry run is a first-class outcome**, not a debug flag: it assembles the exact payload, validates it, writes a `published_assets` row with `meta_post_id NULL`, and returns what *would* have been sent — with no Graph write. That row is the only publish evidence a reviewer or CI job can produce without posting to a live Page.

- **Files**: `_shared/meta-publish.ts` (pure gates + payload builders + shared Graph IO, `AbortSignal.timeout` on every call per bugs #35/#41), `_shared/meta-publish_test.ts` (18 credential-free tests), `meta-publish/index.ts`, `meta-publish-targets/index.ts`.
- **`meta-publish-targets`** is deliberately a SEPARATE function: folding "reconfigure where we post" into the endpoint that posts would put the gate and the thing that moves the gate behind one permission check. `list` returns only allowlisted Pages the token actually reaches (`/me/accounts`, never free-text ids); `set` re-checks reachability AND the allowlist server-side. **Admin-only, checked explicitly** — it holds the service-role key and bypasses RLS, so `org_integrations`' admin-only policies (bug #42) do not protect it.
- **Instagram is two calls**: media container → poll `status_code` until `FINISHED` (10 × 2s cap, per bug #2's wall-clock lesson) → `media_publish`. An IG publish rides the linked **Page's** token, which is why `publishOptions()` refuses to offer IG without a Page target.
- **Page tokens are derived per call** (`GET /{page}?fields=access_token`), never stored: they change when permissions change, and a stale stored copy fails in ways that look like a permission bug.
- **Client**: `src/lib/publish-targets.ts` (pure `publishOptions`/`canOfferPublish`/`buildDefaultCaption`, tested; plus the RPC read and the invoke). Targets are read through **`meta_connection_status()`**, not `org_integrations` — that table is admin-only, so a direct read would hide the Post button from every member. `MetaPostDialog.tsx` is the approval surface: target named explicitly, Post disabled until it is, **dry-run defaults ON every open** (not remembered between opens — a sticky live flag would silently skip the rehearsal on the second post), editable caption prefilled from ad copy.
- **Button visibility is HIDDEN, not disabled**, when no target is configured: a greyed-out button with no explanation is a support ticket, and the person looking at a creative usually cannot set an org-level target anyway.
- **Cost ledger**: one `agent_interactions` row per live publish, `provider='meta'`, `call_type='publish'`, `cost_usd=0`. A Graph publish costs nothing, but "free" and "unrecorded" are different facts. Migration `20260828120000` widened both CHECKs; `_shared/api-cost.ts`'s unions and `database.types.ts` must move with them.
- **Not recorded**: a Graph failure *after* the gates writes no `published_assets` row (the error is returned and logged). Making "we tried and Meta refused" queryable wants its own status column — `NULL meta_post_id` already means dry run.

**THREE MODES, not two** (RB-PUB STEP 2). `dry_run` proves the payload assembles but never asks Meta; a live post asks Meta and shows the public. The missing middle is **`draft`**, which Graph already supports: Facebook `published=false` on the same endpoint (a real post id, invisible on the Page), Instagram stopping after the media container (a real `creation_id` — publishing is a *separate second call*, so not making it is not a workaround, it is just not finishing). Draft produces genuine Graph evidence for a screencast with no public artefact.
- Going live needs **two independent gates, different owners**: `META_PUBLISH_MODE=live` on the deployment (standing permission, set by someone with project access) AND `confirm_live` on the call (per-action intent). Either missing ⇒ draft. Anything unrecognised in `META_PUBLISH_MODE` — unset, typo'd, empty — resolves to `draft`, same fail-closed reasoning as the allowlist.
- A live request that fails either gate **DOWNGRADES with a warning, never errors**. Erroring would train people to retry until something works, which is the opposite of what a confirmation gate is for — and the draft it produced is usually the evidence they wanted.
- `published_assets.published` (migration `20260828140000`) carries this: `dry_run` answers *did we call Graph at all*, `published` answers *can anyone see it*. Three valid states; a schema CHECK forbids the impossible fourth (`dry_run AND published`). Both flags derive from one `mode` in `buildPublishedAssetRow`, so they cannot disagree.
- **Drafts are logged to the cost ledger too** (`feature='meta-publish-draft'`, `cost_usd=0`) — a draft is a real Graph call, and the ledger answers "what did this app do", not "what did this app pay for".

**Page token comes from `/me/accounts`, with a capability check** (RB-PUB STEP 3). `GET /{page}?fields=access_token` answers *is there a token* and nothing else — a token exists for a Page the System User can only ANALYZE, so that request succeeds and the failure arrives from the POST as a generic permissions error, at the exact moment the user has just confirmed a live post. `/me/accounts?fields=id,name,access_token,tasks` returns the token and the capability in the SAME response: `tasks` must include `CREATE_CONTENT`, else `403 page_missing_create_content`, before anything is sent. Costs no extra round trip.

**`GRAPH_API_VERSION` is one constant** (`_shared/graph-version.ts`, **v26.0**) used by `meta-oauth.ts` (API host *and* the login-dialog host — different domains, same version), `meta-publish.ts` and `meta-sync-core.ts`. The dead client-side copy (`src/lib/meta-api.ts`, zero references anywhere) was deleted rather than bumped. **v26.0 was verified live, not assumed**: probing `/{version}/oauth/access_token` with no credentials separates a routed version (`code 101 "Missing client_id"`) from an unrouted one (HTTP 500 `code 1`) — v21–v26 route, v27+ do not. A *token-bearing* probe cannot tell you this; an invalid-token error (code 190) short-circuits before version routing, so `v99.0` looks exactly as healthy as `v21.0`. **The sync path rides this constant too**, so a future bump moves campaign reporting at the same time — re-verify a real sync after changing it. **Done for v26.0 — VERDICT: PASS**, below.

## RB-P3 — universal cost ledger

**RB-P3 — Universal cost ledger (migration `20260807140000`)**: `agent_interactions` is now the SINGLE row-per-external-API-call ledger for the WHOLE app, not just LeadGen-V2. No parallel tables. New nullable columns: `provider` (`anthropic|openai|gemini`), `call_type` (`text|image_gen|image_edit|vision`), `feature` (attribution string), `project_id` (FK), `image_count`, `unit_cost_usd`. `agent` is now **nullable-with-meaning**: agent-pipeline rows carry `agent` (feature null), all other rows carry `feature` (agent null) — the Usage surface coalesces `feature = COALESCE(feature, agent)`. `cost_usd` is now nullable too — an unknown model logs the row with a **NULL** cost + a `console.warn` (never silently skipped). Additive/backfill-nothing; existing specialist inserts are untouched and still valid.
- **Write path**: `agent_interactions` gained an org-scoped INSERT RLS policy (`org_id = get_current_user_org_id() AND (user_id = auth.uid() OR user_id IS NULL)`) so client calls log their own rows, same trust model as `ai_sessions`/`logAiSession`. Service-role writes (aarav-orchestrate, crons) still bypass RLS.
- **Pricing**: `src/lib/pricing.ts` (client) + `supabase/functions/_shared/pricing.ts` (edge) — mirrored pure maps (`MODEL_PRICING` per-token, `OPENAI_IMAGE_COST_USD`/`GEMINI_IMAGE_COST_USD` per-image). Can't share one file across the Vite/Deno boundary; `pricing.test.ts` + `pricing_test.ts` pin identical known values so drift trips CI. **Update BOTH when a price changes.** The old flat `claudeCostUsd = (in*3+out*15)/1e6` (Sonnet rate applied even to Haiku) is superseded for new call sites by model-aware `textCostUsd`.
- **Helpers**: `recordApiCost()` — client (`src/lib/api-cost.ts`, fire-and-forget insert) + edge (`_shared/api-cost.ts`, `async`, fire-SAFE never-throws, awaited-and-asserted in tests). Wired at the **choke points**, so all 41 client call sites are covered by instrumenting a handful of functions:

  - The 2 direct-invoke callers (`Analyzer.tsx` meta_research, `AanyaMemory.tsx` aanya_memory_vision) call `recordApiCost` explicitly.
  - Client images: `gemini-service.generateImageWithGemini` passes `orgId/userId/feature/projectId` to `generate-image`, which writes the row (edge helper) — it knows the real provider/quality/unit cost. `call_type` = `image_edit` (hero) vs `image_gen`.
  - Server: `meta-insights-sync` Arjun-promotion Haiku vision (`arjun_promote_vision`); `dhruv-weekly-report` extended with `provider/call_type/feature`.
- **Ceilings**: chatbot has a real **server-side org-daily cap** — `check_daily_feature_cap(feature, cap)` (SECURITY DEFINER RPC, counts the org's `feature='chatbot'` rows today IST) called from `AIChatbot` before the call (fail-open on transient RPC error), replacing the bypassable localStorage 30/day as the authoritative gate. Regenerate-template + reference-analysis are tagged as creative-pipeline spend (`regenerate_template`/`reference_analysis`); the image path is already `reserveImageBudget`-capped.
- **Usage surface**: `src/components/settings/UsageSection.tsx` (admin-only, `profiles.role='admin'`, renders null otherwise) in `SettingsPage`. Client-side aggregates (`src/lib/usage-aggregate.ts`, pure + unit-tested) over one bounded 35-day fetch — this-month by feature/provider/project, 30-day daily CSS-bar trend, top-10 costliest w/ drill-down. No new infra, no exports.
- **Tests**: `pricing.test.ts`/`api-cost.test.ts`/`usage-aggregate.test.ts` (client) + `pricing_test.ts`/`api-cost_test.ts` (edge). Terminal-write rule honored — assert the ledger ROW payload, not the invocation.
